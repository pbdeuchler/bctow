I'd like you to make the core API generically typed using the Sized trait to allow for pre-allocation and existing performance characteristics.

Plan

1. Reintroduce a typed core instead of wrapping the existing byte API.
   Make broker, Producer, ConsumerContext, ConsumerClient, BrokerInner, TopicRegistry, TopicEntry, and RingBuffer generic over T. TopicId and TopicKey stay unchanged.
2. Replace byte slots with inline typed storage in src/ring.rs.
   Change Slot from len + Box<[u8]> to UnsafeCell<MaybeUninit<T>> plus the existing version/readers/sequence atomics. Remove len and max_payload_size. This keeps the current overwrite/read coordination, but the
   storage becomes fixed-size and fully preallocated per slot.
3. Keep the publish path copy-based and allocation-free.
   Change publish and publish_id in src/producer.rs to accept &T on the hot path, then copy one T into the slot with ptr::copy_nonoverlapping or equivalent. Keep the existing producer ring cache; it already
   preserves the no-lock fast path for publish_id.
4. Make the consumer scratch typed instead of byte-backed.
   In src/consumer.rs, replace Vec<u8> scratch with a single MaybeUninit<T> scratch cell per client. poll() becomes Option<ReceivedMessage<'\_, T>>, where the borrowed field is &T from scratch. The typed equivalent
   of poll_into should write into &mut MaybeUninit<T> and return only the TopicId, since message length is no longer dynamic.
5. Remove byte-specific config and errors.
   max_payload_size, PayloadTooLarge, and ReceiveBufferTooSmall are artifacts of variable-length bytes and should be removed from src/config.rs and src/error.rs. The broker memory bound becomes
   ring_buffer_capacity \* size_of::<T>() per topic, which is compile-time known for the message type.
6. Rename byte-oriented API language.
   payload should become message or value, because the API is no longer fundamentally byte-oriented. The docs in src/lib.rs, README.md, tests, and examples should move to fixed-size typed messages such as u64 or a #[derive(Copy, Clone)] struct.
7. If compatibility with variable-length byte payloads still matters, keep it out of the core.
   Build a typed wrapper message like FixedBytes<const N: usize> { len, bytes: [u8; N] } on top of the typed ring instead of keeping &[u8] as the core storage model. That preserves a byte-oriented facade without
   reintroducing dynamic slot sizing.
8. Add explicit no-allocation verification.
   After topic creation, subscription, and producer cache warm-up, add tests that count allocations around repeated publish_id, poll, and poll_into calls. That is the only reliable way to prove the refactor did
   not add hidden allocations to the steady-state hot paths.
